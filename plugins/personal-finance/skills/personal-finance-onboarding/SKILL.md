# 사회 초년생 자산관리 온보딩

사회 초년생에게 필요한 현재 자산·부채·지급 가능성을 확인하고 개인용 지속 관리 스킬이 바로 사용할
수 있는 버전된 인계 데이터를 만듭니다.

## 시작 전

이 `SKILL.md`를 기준으로 다음 공통 파일을 먼저 읽습니다.

- `../personal-finance-core/SPEC.md`
- `../personal-finance-core/handoff.schema.json`

공통 명세와 이 문서가 충돌하면 공통 명세를 따릅니다.

## 금지 사항

- 송금, 납부, 상품 가입, 투자 주문, 계좌·카드 해지를 실행하지 않습니다.
- 전체 계좌번호, 전체 카드번호, 비밀번호, CVC, OTP, 로그인 정보를 묻지 않습니다.
- API 키와 인증 토큰을 인계 데이터에 넣지 않습니다.
- 사용자가 확인하지 않은 금액을 추정해 확정값으로 만들지 않습니다.
- 일반 자산관리 범위를 넘어 채무조정, 회생·파산, 세무, 사업 회계, 법률 판단을 대신하지 않습니다.

계좌와 카드는 사용자가 알아볼 수 있는 별칭만 받습니다. 실제 금융 행위가 필요하면 사용자가 직접
실행해야 할 항목으로 안내하고, 실행 결과를 확인한 뒤에만 반영합니다.

## 대화 원칙

- 내부 스키마와 회계 용어를 사용자에게 그대로 묻지 않습니다.
- 한 번에 같은 화면이나 앱에서 확인할 수 있는 정보만 묶어 질문합니다.
- 사용자가 이미 제공한 정보는 다시 묻지 않습니다.
- 답변이 충분하면 바로 기록하고 실제 계산을 바꾸는 누락만 짧게 확인합니다.
- 값이 아직 나오지 않은 이유와 다음 확인 시점을 알면 `확인된 미정`으로 처리합니다.
- 온보딩 진행 상황을 `차단 필수`, `확인된 미정`, `후속 확인`으로 구분해 보여줍니다.

## 온보딩 순서

### 1. 범위와 기준시점

사회 초년생의 개인 자산관리인지 확인하고 기준 시간대, 통화, snapshot 기준일시를 정합니다. 개인사업
회계나 법률 판단이 주목적이면 일반 흐름을 시작하지 않습니다.

### 2. 현금과 계좌

현금과 각 계좌의 별칭, 기준시점 잔액, 개별 확인 시점, 출금 제한을 확인합니다. 잔액은 현금성 여부,
즉시 출금 가능 여부, 사용 목적을 따로 기록합니다. 자유 자금, 비상금, 고정비 준비금, 경조사 준비금
같은 목적성 자금을 계좌 잔액과 중복 차감하지 않도록 position으로 나눕니다.

현재 잔액을 확인할 수 없으면 차단 필수로 남깁니다. 미청구 이자처럼 현재 값이 존재하지 않는 경우에는
값 성격과 다음 확인 시점을 기록합니다.

### 3. 카드와 부채

카드별 별칭, 현재 미결제 원금, 결제일과 결제 계좌를 확인합니다. 기존 할부, 리볼빙, 현금서비스,
카드론, 학자금과 일반 부채는 다음 내용을 확인합니다.

- 현재 원금
- 미지급 이자와 수수료
- 전체 회차와 남은 회차
- 금리와 최소 결제액
- 다음 상환일
- 연체 여부

카드성 부채는 `payment_account_id`와 구조화된 `next_payment.amount`, `next_payment.due_at`을
기록합니다. 다음 수입 전에 결제할 카드 금액은 필수 의무에도 같은 부채 ID로 연결합니다.
모든 부채는 `accrued_interest`, `fees_due`, `overdue`를 기록합니다. 할부·리볼빙·현금서비스·카드론의
`annual_rate`, `total_installments`, `remaining_installments`, `minimum_payment`는 항상 키를 보존하고,
적용되지 않는 값은 `null`로 명시합니다. 별도의 `next_due_at`은 사용하지 않습니다.

신규 사용을 권하지 않는 원칙과 기존 의무 추적을 구분합니다. 현재 부채와 다음 지급 가능성을 계산할
수 없으면 온보딩을 완료하지 않습니다.

### 4. 소득과 반복 의무

정기 급여, 불규칙 소득, 지원금의 금액 범위와 입금 시점을 확인합니다. 월세, 공과금, 통신비, 보험,
가족 부양비, 구독, 교통비처럼 반복되는 의무는 금액, 지급일, 결제수단, 필수 여부를 기록합니다.

아직 청구되지 않은 공과금은 임의의 확정값을 만들지 않습니다. 상한이나 변동 기준과
`next_review_at`을 기록합니다.

### 5. 목표와 예산 원칙

비상금, 부채 상환과 중장기 목표의 우선순위를 확인합니다. 건강 유지, 의료, 필수 교통처럼 임의로
삭감하지 않을 항목을 보호 범주로 기록합니다. 금융상품은 사용자가 명시적으로 원할 때만 최신 조건을
검증해 다룹니다.

포인트 기본 정책은 현금 중심입니다. 포인트 적립은 참고정보, 현금화와 계좌 캐시백은 기타수입,
포인트 사용은 실제 현금·카드 결제액만 지출로 처리한다고 설명합니다.

### 6. 결산과 실행 환경

결산 주기를 `매번`, `매일`, `매주`, `매월` 중에서 선택받아 각각 `every_event`, `daily`, `weekly`,
`monthly`로 기록합니다. 직접 호출은 `direct`, Hermes 같은 자동화 환경은 `automated`로 기록합니다.

자동화 모드에서는 알림 시각과 필요한 경우 요일을 확인합니다. 같은 `period_id`에는 능동 알림을 한
번만 보낸다는 규칙을 설명합니다. 일반 거래는 결산 주기에 모을 수 있지만 지급 가능성을 바꾸는 소득,
고정비, 부채, 결산 전 확정 의무는 즉시 입력해야 합니다.

### 7. 저장소 선택

Outline, Notion, 로컬 Markdown 또는 다른 저장소 중 사용 환경을 기록합니다. 지원 어댑터가 아직
없으면 `storage.adapter=unconfigured`로 두고 표준 JSON을 결과로 제공합니다. 인증정보는 저장소 위치와
분리합니다.

### 8. 위험 확인

다음 수입 전에 필요한 필수지출과 정책상 사용 가능액을 비교합니다. 연체 발생·임박, 필수지출 부족,
사용자가 정한 횟수 이상의 연속 적자, 일반 예산으로 해결할 수 없는 지급 불능을 확인합니다.

채무조정, 회생·파산, 세무 신고, 개인사업 회계, 법률 판단이 필요하면 인계 생성을 멈추고 전문 지원이
필요한 이유를 설명합니다.

인계 데이터의 `cashflow_horizon`에 다음 수입의 예상 금액·일시, 다음 수입 전 필수 의무의 금액·
지급일·지급 계좌를 기록합니다. opening position에서 계산한 정책상 사용 가능액과 필수 의무 합계를
`payment_capacity`에 기록하고 `can_cover`가 두 금액과 일치하는지 확인합니다.

## 완료 조건

다음 항목을 모두 충족해야 온보딩을 완료합니다.

- 현재 자산과 현금성·유동성·정책상 사용 가능액 계산 가능
- 현재 카드 미결제액과 다른 부채 계산 가능
- 다음 수입 전 필수지출 지급 가능성 계산 가능
- 모든 비확정값에 값 성격과 다음 확인 시점 기록
- 차단 필수 체크리스트 완료
- 결산 주기와 실행 모드 확정
- 금지된 민감정보 없음
- `snapshot`, `accounts_and_positions`, `liabilities`, `next_income`, `essential_obligations`,
  `payment_capacity` 표준 차단 항목 완료
- 모든 계좌에 opening position 존재

후속 확인 항목은 남을 수 있지만 시작 상태를 왜곡해서는 안 됩니다.

## 결과

`handoff.schema.json`을 따르는 `schema_version=1.0.0` JSON과 사람이 읽을 수 있는 요약을 만듭니다.
요약에는 snapshot 기준일시, 총자산, 총부채, 순자산, 정책상 사용 가능액, 다음 수입 전 필수지출,
목적성 자금, 결산 주기, 후속 확인을 포함합니다.

이 `SKILL.md`가 있는 디렉터리에서 인계 JSON을 만든 뒤 다음 명령으로 검증합니다.

```bash
node ../personal-finance-core/validate-handoff.mjs <handoff.json>
```

검증에 실패하면 오류가 난 항목만 다시 확인합니다. 검증을 통과한 인계 데이터만 개인용 지속 관리
스킬에 전달합니다.
